# ניתוח קוד: רלוונטיות, איחוד, פיצול ושיפורים

מסמך סקירה לפרויקט **qr_party** (מצב נכון ל־מאי 2026). מטרה: לזהות קבצים/חלקים פחות רלוונטיים, כפילויות, נקודות לאיחוד או לפיצול, ושיפורים ארכיטקטוניים. **עודכן:** פיצול Twilio מ־`useGuestListPageModel` ל־`useGuestListTwilio.ts` (ראו §3.1).

---

## 1. קבצים ונכסים שכמעט אינם רלוונטיים או Legacy

### 1.1 `public/send_whatsapp.py`

- סקריפט Python לשליחת הודעות מקומית (`data.json`, וכו׳).
- אם כל שליחת ההזמנות עוברת כיום דרך **Twilio** (Edge Functions, תור `whatsapp_send_queue`), הסקריפט הוא **שארית תהליך ידני** — שימושי רק למי שעדיין מריץ שליחה מחוץ לאפליקציה.
- **המלצה:** להעביר ל־`docs/scripts/` או ל־`tools/` עם README קצר; או להשאיר ב־`public/` רק אם באמת משרתים הורדה ציבורית (כרגע `vercel.json` מפנה אליו במפורש).

### 1.2 `public/favicon.svg` ו־`vercel.json`

- ב־`index.html` הפאביקון הוגדר ל־`/image.png` (וגם `apple-touch-icon`).
- `vercel.json` עדיין מכיל rewrite ל־`/favicon.svg`.
- **המלצה:** לאחד — או להסיר את הכלל אם אין קישורים חיצוניים ל־`favicon.svg`, או להפנות `/favicon.svg` ל־`/image.png` לתאימות ספריות ישנות.

### 1.3 `public/images/brand/logo.svg`

- ברירת המחדל באפליקציה עברה ל־`public/image.png` דרך `publicAppIcon()` ב־`src/lib/publicAssetUrl.ts`.
- הקובץ `logo.svg` **עדיין קיים** ומתאים לשימוש אם יועלה אייקון מותאם ב־CMS / שיווק — לא "מת", אבל **התיעוד** ב־`public/images/brand/README.txt` עדיין מדגיש `logo.svg` כברירת מחדל ראשית.
- **המלצה:** לעדכן את ה־README כך שישקף `image.png` + מסלולי Supabase לשיווק.

### 1.4 `src/assets/react.svg`

- לא נמצא שימוש בייבוא מתוך `src/` (סריקת `react.svg`).
- **המלצה:** למחוק אם אין תכנון להשתמש, או להשאיר במסגרת תבנית Vite רק אם נדרש לדוגמאות.

### 1.5 דפי / רכיבי **Mock** לתשלום שותף

- `PartnerPaymentLandingMockPage.tsx` — רoute פעיל ב־`App.tsx`: `/ticket/partner/:partnerSlug`.
- `PartyPaymentNextMockButton.tsx`, `mockPartnerPayRoundRobin.ts`, `mockPartnerAcquirers.ts` — מוק; הכפתור **מוערם בהערות** ב־`PartyLayout.tsx`.
- **רלוונטיות:** גבוהה לפיתוח, נמוכה לפרודקשן "נקייה".
- **המלצה:** לעטוף ב־`import.meta.env.DEV` / feature flag, או להעביר לסביבת staging בלבד.

## 2. כפילויות לאיחוד (DRY)

### 2.4 אייקוני צ'אט כפולים

## 3. קבצים גדולים — פיצול מומלץ

### 3.1 `src/hooks/useGuestListPageModel.ts` (~1,410 שורות) + `useGuestListTwilio.ts` (~270 שורות)

אחראי על: נתוני מסיבה, רשימת אורחים, חיפוש, סינונים, הדבקה המונית, כרטיסים, מחיקות, לוגים, טוסטים, מחירים/שותפים, ועוד. **לוגיקת Twilio** הוצאה ל־`useGuestListTwilio.ts` (מאי 2026): `rowSendTwilio`, שליחה אוטומטית אחרי יצירת זהות ראשונה (יתרה + תבנית מאושרת), סנכרון סטטוס תבנית מול Twilio/Meta, ו־Realtime לסטטוס הזמנה ב־`whatsapp_messages` — תוך שמירה על אותו API ל־`GuestListPage` (ה־model עדיין מחזיר `rowSendTwilio`, `twilioSendingGuestId`, `twilioTemplateApproved`).

**כיווני פיצול נוספים (עתידיים):**

| מודול חדש (הצעה) | אחריות |
|-------------------|--------|
| `useGuestListTwilio.ts` | **בוצע** — שליחה, יתרה, תבנית מאושרת, `rowSendTwilio`, Realtime סטטוס הזמנה |
| `useGuestListPasteBulk.ts` | `pasteText`, `onPasteBulk`, הודעות שגיאה |
| `useGuestListTickets.ts` | `handleAddTicket`, `handleRemoveOneTicket`, מצבי pending |
| `useGuestListFilters.ts` | סינוני כניסה, הזמנה, מקבל, מיון |
| `guestListPageModelTypes.ts` | טיפוסים משותפים אם ייווצרו |

יתרון: בדיקות יחידה, קריאות, פחות קונפליקטים ב־git. חיסרון: צריך לתזמן `queryClient` / מפתחות cache בצורה עקבית — בפיצול Twilio מועברים `persistGuestRows`, `showMobileToast`, `setError` כפרמטרים.

### 3.2 `supabase/functions/_shared/twilioInviteSend.ts` (~440+ שורות)

- שילוב: נרמול, תבנית Twilio, בניית גוף הודעה, audit, שליחה, עדכון DB.
- **המלצה:** לפצל ל־`twilioInviteBody.ts`, `twilioInviteAudit.ts`, `sendWhatsAppInviteCore.ts` — לפי שלב (`phase`) שכבר קיים בשגיאות.

### 3.3 מיגרציה `20260430130000_audit_rich_metadata.sql` (~1,000 שורות)

- מסמכת/מגדירה הרבה audit — לגיט זה כבד אך חד־פעמי.
- **לא "לא רלוונטי"** — אבל קשה לנווט. **המלצה:** לעתיד, פיצול מיגרציות לוגיות (טבלאות / פונקציות / grants) לקבצים קטנים יותר עם אותו timestamp prefix או גרסאות עוקבות.

## 4. CSS — ארגון ושיפור

### 4.1 כפילות מסלולים: `src/styles/partials/` ו־`src/styles/mobile-guest/partials/`

- `index.css` מייבא בעיקר `partials/`; `mobile-guest.css` מייבא את תת־התיקייה `mobile-guest/`.
- שמות כמו `09-sheet-rows-modals-python-snippet.css` מרמזים על **היסטוריה** (סניפט Python) — לא בהכרח לא רלוונטי, אבל **מבלבלים**.

**המלצות:**

- למפות "איזה partial שייך לאיזה דף" בטבלה קצרה ב־README של `styles/`.
- לאחד חלקים חופפים בין דסקטופ למובייל אם אותם selectors חוזרים (בזהירות — הרבה עיצוב מכוון להפרדה).

### 4.2 BEM / שמות

- שילוב של `guest-mob-*`, `guest-desk-*`, `guest-manage-page` — עקבי יחסית, אבל ארוך.
- **שיפור איטי:** דוקומנטציה של קידומות (מפתחות) לעורכי CSS.

## 5. Edge Functions — עקביות ואבטחה

### 5.1 פונקציות עם הרשאות שונות

- `mark-whatsapp-invite-sent` — לפי ההערה בקוד, גרסה עם service role ללא אימות מלא של המשתמש; **סיכון אם URL נחשף**.
- **המלצה:** לעבור על מדיניות: JWT חובה, או מפתח סודי לסקריפטים בלבד, ותיעוד ב־README של Supabase.

### 5.2 אכיפת הרשאות UI מול DB

- חלק מהכללים (שותף בלבד לכרטיסים, כניסה רק בסריקה, הזמנה ידנית במצב "נצפה") מיושמים ב־**פרונט** בלבד.
- **שיפור:** RLS או טריגרים / RPC שמגבילים עדכון `status` / `entered_at` / `whatsapp_invite_sent_at` לפי תפקיד — כדי שלא יעקפו דרך API ישירות.

## 10. מה *כן* נשאר רלוונטי (לא למחוק בסתירה)

- `public/icons.svg` — סמלילים ל־landing / קישורים חברתיים.
